\chapter{Conclusion}\label{ch:conclusion}

\section{Achievements}
This dissertation addressed the problem of obtaining stronger executable-level safety guarantees for systems programs without trusting a full compiler or building a fully verified one. Veritas moves the trust boundary below the frontend: the compiler may remain untrusted, provided that the emitted low-level artifact carries enough information to be checked independently. The project successfully implemented this architecture end to end: a refinement-typed imperative source language, a type-preserving compiler pipeline, a DTAL-inspired low-level target, an independent verifier, and hosted and bare-metal execution targets. Safety-relevant facts such as contracts, array-bounds obligations, arithmetic side conditions, and ownership information are preserved through lowering and re-checked at the low level. Beyond the core goal, the implementation also added physical DTAL after register allocation, ownership-aware low-level operations, I/O and runtime support, and a bare-metal/unikernel path, pushing more real backend behaviour into the checked artifact.

\section{Future work}

While out-of-scope for this project due to time constraints, I considered several avenues for future work:

\begin{itemize}
  \item \textbf{Richer source-language fragment.} The most direct extension is to support a broader set of systems-programming idioms, including non-lexical lifetimes, reborrowing, richer heap-allocated data structures, and more expressive aliasing patterns.
  \item \textbf{Broader verified property classes.} Future versions could extend beyond the current memory-, arithmetic-, and contract-safety focus to support concurrency properties, information-flow policies, and cryptographic correctness or side-channel-oriented specifications.
  \item \textbf{Type-directed optimisation.} The backend could make better use of facts already proved by the frontend and DTAL verifier, such as bounds, singleton values, and refinement constraints, to improve generated code without weakening the trust architecture.
  \item \textbf{Verifier formalisation.} A longer-term assurance goal is to formalise the verifier or its core metatheory in a proof assistant, reducing the amount of trust placed in the implementation itself.
    % \item \textbf{Broader evaluation.} The empirical case for Veritas would be strengthened by larger benchmarks, more verification corpora, and additional external comparison systems.
    % \item \textbf{Public release.} Preparing the implementation for public release would make the toolchain easier to reproduce, evaluate, and extend beyond this dissertation.
\end{itemize}

\section{Reflections}
Veritas is by far the largest and longest-running software project I have undertaken, and it allowed me to apply programming-language and compiler theory in a concrete implementation. The main lesson was that language design, verification, and backend engineering cannot be treated separately: decisions in the source language or type system quickly affected the DTAL representation, verifier, code generator, runtime, and debugging workflow. If I were starting again, I would define the evaluation plan earlier and use it more actively to control scope, since some extensions in the initial proposal were too ambitious for the time available (e.g., richer concurrency or behavioural properties). I would, however, keep the engineering practices that made the project manageable, especially regular testing, reproducible benchmark scripts, and small regression cases.
