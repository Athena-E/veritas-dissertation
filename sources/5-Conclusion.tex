\chapter{Conclusion}\label{ch:conclusion}

This dissertation addressed the problem of obtaining independently checkable low-level safety evidence for systems programs without maintaining a fully verified compiler. Veritas moves part of the trust boundary below the frontend: the compiler may remain untrusted for the checked V-DTAL safety policy, provided that the emitted low-level artifact carries enough information to be checked independently. The project implemented this architecture end to end: a refinement-typed imperative source language, a verifier-facing compiler pipeline, a DTAL-inspired low-level target, an independent verifier plus extensions that included bare-metal execution targets and a borrowing/ownership model. The system preserves safety-relevant facts such as contracts, array-bounds obligations, arithmetic side conditions, and ownership information through lowering and re-checks them at the low level, while still remaining practical as a systems-language toolchain.

\section{Future work}

\begin{itemize}
  \item \textbf{Richer source-language fragment.} The most direct extension is to support a broader set of systems-programming idioms, including non-lexical lifetimes, reborrowing, richer heap-allocated data structures, and more expressive aliasing patterns.
  \item \textbf{Broader verified property classes.} Future versions could extend beyond the current array-bounds, arithmetic, contract, and ownership evidence to support concurrency properties, information-flow policies, and cryptographic correctness or side-channel-oriented specifications.
  \item \textbf{Type-directed optimisation.} The backend could make better use of facts already proved by the frontend and V-DTAL verifier, such as bounds, singleton values, and refinement constraints, to improve generated code without weakening the trust architecture.
  \item \textbf{Verifier formalisation.} A longer-term assurance goal is to formalise the verifier or its core metatheory in a proof assistant, reducing the amount of trust placed in the implementation itself.
\end{itemize}

\section{Reflections}
Veritas is by far the largest and longest-running software project I have undertaken, and it allowed me to apply programming-language and compiler theory in a concrete implementation. The main takeaway was that decisions in the source language or type system quickly affected the V-DTAL representation, verifier, code generator, and debugging workflow. If I were starting again, I would define the evaluation plan earlier and use it more actively to control scope, since some extensions in the initial proposal were too ambitious for the time available (e.g., richer concurrency or behavioural properties). I would, however, keep the engineering practices, which made the project manageable. Discussing the project with others, including through regular standups and presenting a poster at the OxBridge Women in Computer Science Conference 2026\footnote{\url{https://www.cs.ox.ac.uk/event/52-full.html}}, was also valuable because it forced me to explain the trust model and motivation clearly to a diverse audience.
